# durable-turns

Stop tying the lifetime of a turn to the lifetime of a UI client.

## Why

Every automatic interrupt path in the upstream Codex bundles encodes one
assumption: when nobody is watching, stop the work. For the OpenCodex web
deployment that assumption is inverted. Many concurrent browser viewers plus
background and headless sessions are the normal case, so losing a viewer is
routine rather than exceptional. Measured on the 235.t production box, the
gateway logged 888 orphaned app-host relays against only 470 reattachments,
and a single lost viewer could take down a whole subagent tree: on
2026-10-06 15 threads were interrupted inside a single second.

The turn itself is executed by the long-lived app-server process, not by the
page. A viewer going away is therefore not a reason to stop working.

## Why there are no anchor strings in this directory

The previous implementation anchored on exact minified strings inside fixed-name
files (`main-*.js`, `app-initial-*.js`). On 2026-10-08 the 241.t fleet moved from
upstream 26.908.40834 to 26.1002.52244, roughly 94 releases, and every anchor went
to zero at once: upstream re-chunked the bundle, moving the main-process code from
`main-DaMR-wdT.js` into `bootstrap-CTpobVUg.js` and the webview logic from
`app-initial-74b69e67976a.js` into `app-shared-cc1fe93eb683.js`.

What did not drift across those 94 releases is the symbol surface.
`interruptConversationSelf`, `discardConversationFromCache`,
`shouldKeepConversationLoaded` and `interruptSubagentDescendants` all survived,
untouched, because rollup does not rename property and method names. Only the
file names and the minified locals rotate. So the patcher anchors on symbols and
structure, and treats file names as an implementation detail of a release.

## Architecture

    signatures.gen.js  ->  signatures.json   the rule library (data, versioned)
    lib/segments.js    the shape language: one representation that both matches and renders
    lib/chunks.js      offset-exact chunked reader/writer for single-line multi-MB bundles
    lib/locate.js      carrier screening and region resolution (open / close / invariants)
    lib/plan.js        rewrite planning, terminal-state assertion, reverse round-trip check
    lib/reverse.js     revert: match the patched shape, render the upstream shape
    patch.js           loadLibrary / patchTree / reverseTree / buildDescriptors
    cli.js             drift report

1. **Locate by symbol, never by file name.** Every `.js` under `.vite/build` and
   `webview/assets` is screened, and a chunk is a carrier only when it holds the
   whole turn-lifecycle contract (`carrierSymbols` in the library). No rule,
   region, or scan entry names a bundle file, and a regression test asserts it.
2. **Locate by structural signature, never by bare string.** Inside a carrier a
   rule names a region: an `open` anchor (function head), a patch-neutral `close`
   token, and `invariants` that must hold between them. Edits then bind by shape
   (`if(<role>?.role!=='follower'||<reason>==null)throw <err>;`), so a minified
   rename costs nothing and a same-shaped function in the wrong scope cannot bind.
3. **Assert the terminal state.** After planning, each rule must show its `gone`
   shapes absent and its `present` shapes present inside its own region, plus any
   `ordered` prerequisites. The old patcher skipped an edit whenever its
   replacement text appeared anywhere in the bundle, which shipped a bundle whose
   guard referenced an undeclared `__dtMode` while reporting success.
4. **Report drift instead of failing opaquely.** `cli.js --check` answers
   BOUND / DRIFTED / REMOVED per rule per carrier, and prints the current source
   of the area with a caret at the failed anchor, so drift is judged by reading a
   few hundred bytes rather than grepping a 19k-file bundle.
5. **Keep the rules as data.** `signatures.json` is generated by
   `signatures.gen.js`; regenerating it is `node signatures.gen.js > signatures.json`.

## The rules

| id | site | change |
|---|---|---|
| P0-a | `interruptConversationSelf` | A follower whose stream owner vanished interrupts locally only for an explicit user stop; every other mode marks `needs_resume` and rethrows. |
| P0-b | `interruptConversation` | The subagent descendant cascade fires only for `user-stop`. Previously any interrupt nuked the whole descendant tree. |
| P1-a | inactive-owner throttle constants | The 3h idle TTL and the 10-thread cap stop recycling background and headless conversations. |
| P1-b | `discardConversationFromCache` | Evicting a cached conversation no longer interrupts an in-progress turn implicitly. |
| P1-c | the discard request | The `ephemeral && isDurableHost` arm that upstream added, which sends a real `thread/stop`, is neutralised. For a durable host this is harsher than the older `thread/unsubscribe`. |

Two details worth keeping in mind when editing these rules.

**P0-a ordering is load-bearing.** The needs-resume mark is emitted *before* the
narrowed throw. Upstream marked and then fell through into a local interrupt, so
hoisting only the guard above the mark would rethrow without marking: the stream
role keeps pointing at the dead owner while `resumeState` stays `resumed`, and
`needsResume()` requires `resumeState === "needs_resume"` or a null stream role,
so both resume gates stay shut in exactly the scenario the rule exists for. The
`ordered` assertion enforces it.

**P1-a uses 2147483647, not `Number.MAX_SAFE_INTEGER`.** Node clamps a
`setTimeout` delay above 2^31-1 down to 1ms with a `TimeoutOverflowWarning`, which
turned a disabled TTL into a ~900 Hz busy loop (11-13% of a core at three idle
conversations, 36% at a hundred). 2147483647 is a legal ~24.8 day delay, so the
timer genuinely stops firing.

## Patched and unpatched

Upstream ships the same logic twice, once per process side, so a rule has to bind
in every carrier or the tree fails. The discard path additionally exists in two
flavours, and P1-c is a *variant group*: exactly one variant may bind per carrier.

| flavour | discard shape | P1-c variant |
|---|---|---|
| 26.908 and older | inline method, always `thread/unsubscribe` | `plain` |
| 26.1002 and newer | module-level helper, `ephemeral && isDurableHost ? thread/stop : thread/unsubscribe` | `upgrade` |

Both land on one verified end state: the `thread/stop` arm is reachable only
through `!1`.

The three suppression counters make the behaviour observable at runtime rather
than only inferable from logs: `globalThis.__dtCascadeUserStopOnly`,
`globalThis.__dtNoDiscardKill`, `globalThis.__dtDiscardMethod`, plus the
`__dtMode` alias in `interruptConversationSelf`.

P1-a also records the values it replaced in a block comment
(`/*durable-turns upstream-throttle 108e5 15e3*/`). A revert renders the upstream
bytes out of the patched text, and an opaque numeric alternation would hold no
text to render, so the original spelling (`108e5` versus `10800*1e3`) would be
unrecoverable.

## Safety properties, and how they are checked

* **required-upstream** - a rule that does not bind, binds ambiguously, or cannot
  reach its end state throws; the build fails rather than shipping a partial fix.
* **Idempotent** - a second apply is a byte-identical no-op. Region `open`
  accepts both the upstream head and this patcher's own output, and P0-a's
  upstream-form anchor carries a `{NOT:let __dtMode=}` guard.
* **Reversible** - `reverseTree` reproduces the upstream bytes exactly. This is
  the same machinery with the two sides exchanged, which is why the library
  refuses at load time to accept an edit whose patched side loses an identifier
  the upstream side consumes.
* **Parseable** - the patched chunk must still pass `node --check` when the
  pristine one did. The gate fires before the write is committed and restores the
  previous bytes on failure; without it a dropped paren once shipped a
  `try{}` with no `catch`.
* **Streaming** - bundles are consumed in 4MB blocks with 256KB overlap, so a
  10MB single-line chunk is never held in memory to run a regex over it.

## CLI

    node cli.js --check   <unpacked-app-asar> [--json] [--signatures <file>]
    node cli.js --dry-run <unpacked-app-asar> [--json]
    node cli.js --reverse --dry-run <unpacked-app-asar> [--json]

Exit codes: `0` every rule bound in every carrier, `1` drift or failure,
`2` usage or environment error. A DRIFTED rule prints the region offset, the
current source around it, and a caret at the failed anchor:

    DRIFTED P0-b in webview/assets/x2.js: durable-turns: P0-b end state not reached: \
      target structure still present (1x): ({CAP:mode}==={LIT:user-stop}?...)
      region at offset 2124052:
      ...(function head}finally{(n==null||r!=null)&&...
                                             ^ anchor

## Tests

    node --test linux-features/*/test.js      # repository gate (scripts/ci/run-node-checks.sh)
    node --test linux-features/durable-turns/test.js

The suite is 34 cases over a synthetic two-flavour bundle: carrier selection,
variant exclusivity, terminal-state and ordering assertions, byte-identical
re-apply, byte-identical revert, the parse gate including its restore path,
ambiguous duplicate regions, rejected irreversible rules at load time, chunk
boundary behaviour, and the CLI exit codes and excerpts.

To check against real bundles, unpack both and run the CLI; both upstream
releases are regression fixtures:

    node cli.js --check /data/tmp/debt/w3/pristine/26.908
    node cli.js --check /data/tmp/debt/w3/trees/26.1002

## Enabling

Committed configuration keeps this feature disabled, per AGENTS.md. Enable it
on the target box only:

    linux-features/features.json  ->  "enabled": ["brand-network-overlay", "durable-turns"]

## Verification after a build

1. Confirm the patch report lists `feature:durable-turns:durable-turns` as
   `applied` (or `already-applied`) and not `failed-required`.
2. Confirm the running bundle carries the markers, not just the built one:
   `grep -lc __dtMode <carrier>.js`. The gateway materializes
   CODEX_WEB_OFFICIAL_BUNDLE_DIR from the asar, keyed by asar size and mtime, so
   replacing the asar makes it re-materialize on the next start.
3. Compare interrupt counters on a patched and an unpatched box over the same
   window: "interrupt received" in the client log database, plus
   app_host_port_reset_requested and turn/interrupt in gateway.log.

There is no ASAR integrity work to do by hand - @electron/asar recomputes the
per-file SHA-256 entries when repacking. Editing the archive in place without
repacking would trip the in-header integrity check and exit(1).
